> Loop 工程（Loop Engineering）是谷歌云 AI 总监 Addy Osmani 于 2026 年提出的一种 AI 智能体自主协作范式，通过“<font color="#ff0000">自动发现 → 任务分派 → 执行 → 验证 → 迭代</font>”的闭环系统，让 AI 自主完成任务，而开发者负责设计循环系统本身。

## Loop 工程的核心定义

Loop 工程是一种 **让 AI Agent 自己跑起来的工程方法论**：

- 不再逐句写 Prompt 驱动模型
- 而是设计一个 **自动化循环系统（Loop）**
- 让 AI 在循环中 **持续感知、推理、行动、验证、迭代**
- 直到任务完成

它是 Prompt → Context → Harness 之后的 **第四层工程范式**，强调从“写提示词的人”转变为“设计自动化系统的人”。

## Loop 工程的六大核心组件

根据 Addy Osmani 的定义，一个完整的 Loop 系统包含六个组件：

| 组件                     | 作用                                  |
| ------------------------ | ------------------------------------- |
| **自动化（Automation）** | 触发循环、调度任务、管理节奏          |
| **工作树（Worktree）**   | 为每个 Agent 提供隔离工作区，避免冲突 |
| **技能（Skills）**       | 可复用的知识/操作模块，减少重复推理   |
| **连接器（Connectors）** | 让 Agent 调用外部工具、API、数据库等  |
| **子代理（Sub-agents）** | 生成者与验证者分离，提高可靠性        |
| **状态记忆（Memory）**   | 保存跨轮次上下文，实现长期迭代        |

## Loop 的运行机制（闭环）

典型循环包含五个阶段：

1. **发现（Discover）**：自动从 issue、CI、队列中找任务
2. **交接（Handoff）**：打包任务、上下文、约束、隔离环境
3. **执行（Act）**：生成代理执行变更
4. **验证（Verify）**：独立验证代理检查结果
5. **持久化与调度（Persist & Schedule）**：写入状态、PR、日志，并按计划再次运行

## Loop 工程与 Prompt 工程的区别

| 维度     | Loop Engineering     | Prompt Engineering |
| -------- | -------------------- | ------------------ |
| 交互方式 | 自动循环、多轮迭代   | 单次输入、静态     |
| 上下文   | 长期记忆、状态持久化 | 依赖 Prompt 长度   |
| 适用场景 | 多步骤、复杂任务     | 一次性、简单任务   |
| 验证     | 内置自动验证         | 人工检查           |

| 维度     | Harness Engineering 驾驭工程                                 | Loop Engineering 循环工程                                    |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 核心定位 | 搭建 Agent 能安全干活的**舞台、基础设施、约束边界**          | 设计 Agent**怎么一步步干活、什么时候停**的执行闭环           |
| 核心问题 | Agent**能碰什么、在哪跑、出问题怎么兜底**                    | Agent**下一步做什么、怎么校验、满足什么条件才算完成**        |
| 产出物   | 沙箱、权限策略、工具注册、状态存储、检查点、重试 / 熔断、观测链路、回放机制、鉴权、人工介入入口 | 目标拆解、迭代流程、校验规则、停止条件、最大轮次、打分验收、分支跳转逻辑 |
| 关注点   | 可靠性、安全、隔离、故障恢复、可观测、资源控制               | 任务收敛、终止条件、迭代策略、目标达成判断                   |
| 典型故障 | 工具调用失败、越权、环境污染、断连无法续跑                   | 死循环、提前终止、反复无效迭代、token 爆炸                   |
| 变更频率 | 偏底层，稳定、少改，一套 harness 支撑多种任务                | 按任务类型定制，不同 Agent 任务可以换不同 loop               |

## 典型应用场景

Loop 工程已在多个领域落地：

- **软件开发**：自动修复代码、运行测试、提交 PR
- **CI/CD 自动化**：依赖升级、PR babysitter、失败测试清扫
- **数据分析**：循环训练模型、自动调参
- **客服系统**：多轮对话自动处理复杂问题
- **科研实验**：无人值守实验控制与数据采集

## Loop 工程的风险与挑战

- **验证债务**：错误可能在自动化中悄悄累积
- **理解腐化**：人类对代码库理解落后于 AI 的修改速度
- **认知投降**：过度依赖自动化导致审查松懈
- **Token 失控**：循环重试导致成本爆炸

这些风险已被系统性总结，并需通过严格的验证器、人工闸门、预算限制等方式控制。

## 总结

Loop 工程是 2026 年 AI 工程化的关键范式，它让 AI 从“被动执行提示词”升级为“主动运行循环系统”。其核心价值在于：

- **自动化**
- **可验证性**
- **可持续迭代**
- **适用于复杂、多步骤任务**

它标志着 AI 开发从 Prompt 驱动走向 **系统设计驱动** 的时代。
