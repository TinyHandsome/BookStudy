    - 取余和取模的区别

      | 项目       | 取余（remainder）                   | 取模（modulo）                          |
      | ---------- | ----------------------------------- | --------------------------------------- |
      | 商怎么取整 | **向 0 截断**（去掉小数部分）       | **向负无穷向下取整**（地板取整 ⌊⌋）     |
      | 结果符号   | **和被除数 a 同号**                 | **和除数 b 同号**                       |
      | 典型实现   | C、C++、Java、JavaScript、Go 的 `%` | Python、Mathematica、数学里的同余 `mod` |
      | 适用场景   | 日常除法剩余值                      | 循环偏移、哈希、周期性计算（最常用）    |

16. 数组、切片的字典赋值法：`arr := []int {0:0, 2:2, 4:4}`，中间的自动填充对应的默认值，比如int就是0

17. 切片的长度：`len(s)`，切片的容量：`cap(s)`。切片的容量是从它的第一个元素开始数，到其底层数组元素末尾的个数。

    ```go
    s := []int{2, 3, 5, 7, 11, 13}
    bs := s[1:3]
    fmt.Println(len(bs), cap(bs)) // 2, 5
    ```

    > 切片本质：一个结构体，包含 3 部分：`指针(指向底层数组) + len + cap`
    >
    > - len：控制课件元素范围；遍历边界；append修改len，当append时，len+1，如果新len<=cap，则底层数组不变，否则触发扩容
    >
    > - cap：是内存预留，用来减少扩容次数，提升性能。 
    >
    >   *如果长度<1024，则每次按2倍来扩容，否则按1/4来扩容。int和string的扩容方式也不同。*
    >
    > 频繁的扩容使用make指定容量，否则会拉低性能

19. 复制切片：`copy(sliceB, sliceA)`，把A的值复制到B中，改变值时两者互不干扰

20. 切片删除值：`append(a[:2], a[3:]...)`，因为go语言中没有删除切片元素的专用方法，可以通过切片本身的特性来删除元素

21. 切片的排序：`sort`包，直接 `sort.Ints(sliceA)` 等等，针对不同的数据类型有不同的方法。降序的方法比较麻烦，还得外面包2层：`sort.Sort(sort.Reverse(sort.Ints(sliceA)))`

24. 给函数定义类型：`type calc func(int, int) int`，用于传参函数类型的变量，比如：`func calculate(x, y int, cb func(int, int) int){...}` 

    匿名函数实现：
    
    ```go
    j := calc(3, 4, func(x, y int) int{
    	return x * y
    })
    ```
    
    上面讲的是参数是函数，如果返回值是函数呢：直接返回函数名、匿名函数等
	
	> 这就对应了 **策略模式**，同一个业务场景，能动态切换不同的计算 / 处理规则。
	>
	> | 角色                         | 在你的代码里对应的部分             | 作用                                                         |
	> | ---------------------------- | ---------------------------------- | ------------------------------------------------------------ |
	> | 策略接口（Strategy）         | `type calcType func(int, int) int` | 定义所有算法必须遵守的统一规范（入参、返回值）。Go 可以用函数类型替代 interface，实现轻量策略 |
	> | 具体策略（ConcreteStrategy） | `sub(x,y int)`、`add`、`mul`       | 封装**具体算法逻辑**，实现策略接口                           |
	> | 上下文（Context）            | `calc(x, y int, cb calcType) int`  | 持有策略，对外提供统一入口；不关心内部算法细节，只调用策略   |
	> | 客户端（Client）             | `main()`                           | 创建并选择具体策略，传给上下文                               |
	>
	> ```mermaid
	> classDiagram
	>     class Strategy {
	>         <<interface>>
	>         +AlgorithmInterface(int, int) int
	>     }
	>     class ConcreteStrategyAdd {
	>         +AlgorithmInterface(int, int) int
	>     }
	>     class ConcreteStrategySub {
	>         +AlgorithmInterface(int, int) int
	>     }
	>     class ConcreteStrategyMul {
	>         +AlgorithmInterface(int, int) int
	>     }
	>     class Context {
	>         -strategy: Strategy
	>         +SetStrategy(s Strategy)
	>         +Execute(a int, b int) int
	>     }
	>     class Client{
	>     }
	> 
	>     Strategy <|-- ConcreteStrategyAdd
	>     Strategy <|-- ConcreteStrategySub
	>     Strategy <|-- ConcreteStrategyMul
	>     Context o-- Strategy
	>     Client --> Context
	>     Client --> ConcreteStrategyAdd
	>     Client --> ConcreteStrategySub
	>     Client --> ConcreteStrategyMul
	> ```

26. :mailbox_closed: <span id="bibao">闭包</span>

    > | 类型     | 特点                                                       |
    > | -------- | ---------------------------------------------------------- |
    > | 全局变量 | 1. 常驻内存<br />2. 污染全局                               |
    > | 局部变量 | 1. 不常驻内存<br />2. 不污染全局                           |
    > | 闭包     | 1. 可以让一个变量常驻内存<br />2. 可以让一个变量不污染全局 |

    1. 闭包是指：有权访问另一个函数作用域中的变量的函数

    2. 创建闭包的常见的方式就是在一个函数内部创建另一个函数，通过另一个函数访问这个函数的局部变量

    3. 注意：由于闭包里作用域返回的局部变量资源不会被立刻销毁回收，所以可能会占用更多的内存，过度使用闭包会导致性能下降，建议在非常有必要的时候才使用闭包

       ```go
       func adder() func() int {
          	var i = 10
          	return func() int {
          		i++
          		return i + 1
          	}
       }
          
       ff := adder()
       fmt.Println(ff()) //12
       fmt.Println(ff()) //13
       fmt.Println(ff()) //14
       ```

27. defer

    - defer最后执行

    - 多个defer，逆序执行

    - defer中的匿名函数如果对函数中的资源有修改，即使return 资源，返回的依然是defer处理前的结果，比如先返回了才执行 ++；但如果是返回值命名了的，则是++后return

      ```go
      func f2() int {
      	var a int
      	defer func() {
      		a++
      	}()
      	return a
      }
      func f3() (a int) {
      	defer func() {
      		a++
      	}()
      	return a
      }
      func f4() (x int) {
      	defer func(x int) {
      		x++
      	}(x)
      	return
      }
      
      fmt.Println(f2())  // 0
      fmt.Println(f3())  // 1
      fmt.Println(f4())  // 0
      ```

31. 结构体

    - 自定义类型：`type myInt int`

    - 类型别名：`type myFloat = float64`

    - 已知 `%v` 可以打印变量的值，`%#v` 可以打印变量的详细信息

    - 实例化的 7 种方法

      1. 直接var，然后一个一个赋值
      2. new，再一个一个赋值
      3. &Person{}，再一个一个赋值
      4. key-value 实例化
      5. & key-value 实例化
      6. 传值部分字段，其他用默认值
      7. 按顺序传值，省略key

    - **结构体是值类型**

      > Go 习惯用接收者类型表达**方法意图**：
      >
      > - `func (p Person) Xxx()`：**这个方法不会修改原对象**
      > - `func (p *Person) Xxx()`：**这个方法可能修改原对象**
      >
      > 值接收者不是用来改数据的。 它的价值： 
      >
      > ✅ 语义声明：只读，不会修改原实例 
      >
      > ✅ 天然隔离：方法内随便改副本，外部不受影响 
      >
      > ✅ 零值安全，nil panic 风险消失 
      >
      > ✅ 小结构体，拷贝几乎无性能代价
      >
      > 缺点： 
      >
      > ❌ 无法修改外部原始实例 
      >
      > ❌ 大结构体拷贝带来开销

    匿名字段（embedded field，嵌入字段），结构体嵌入

    - **基础类型匿名字段** 结构体的字段可以匿名，其中的类型必须是唯一的，不能重复

      ```go
      type Person struct { 
      	string
      	int
      }
      
      pp1 := Person{"张三", 18}
      fmt.Println(pp1.string, pp1.int)
      ```

    - **结构体类型匿名字段** 结构体的特殊结构体字段也可以不写类型，这叫结构体嵌入。

      作用类似继承，就直接把Address的内容嵌入到AA中，不用额外 `a.Address.Age` 了，而是可以直接访问 `a.Age`，如果父子结构体中有命名重复/冲突了，先父后子，子要用复杂的获取方式才行

      ```go
      type AA struct {
      	Username string
      	Password string
      	Address
      }
      
      type Address struct {
      	Name string
      	Age  int
      }
      ```

34. goroutine和channel

    - 多协程和多线程：Golang中每个goroutine（协程）默认占用内存远比 Java 、C的线程少。
      OS线程（操作系统线程）一般都有固定的栈内存（通常为2MB左右）,一个goroutine（协程）占用内存非常小，只有2KB左右，多协程 goroutine 切换调度开销方面远比线程要少。这也是为什么越来越多的大公司使用Golang的原因之一

      > 1. **线程**：操作系统内核管理，切换需要内核介入，开销大；多核可并行。
      > 2. **协程**：用户态程序自己管理，切换不进内核，开销极小；**单线程内并发**，原生不能利用多核。
      >
      > 一句话总结：**线程是 OS 调度的轻量进程；协程是代码层面、在单个线程里手动切换的轻量 “子程序”**。
      >
      > <u>场景：一个工厂车间 = **CPU 核心**</u>
      >
      > **进程**：一间独立厂房，有自己全套设备和资源。
      >
      > **线程**：厂房里的**工人**，由工厂总管（操作系统）安排换班。
      >
      > 换工人要总管出面，交接工具、登记，**切换成本高**；一间厂房（单核）同一时间只能干一个人的活，多间厂房（多核）可以多个工人同时干活。
      >
      > **协程**：**同一个工人**手里的好几份任务清单。
      >
      > 工人自己决定什么时候放下 A 任务，切去做 B 任务，**不用通知总管**，交接几乎零成本。
      >
      > 从头到尾就这一个工人，**没法真正同时干多件事，只是来回穿插着做**。
      >
      > ==线程是 OS 派的不同工人；协程是同一个工人，自己来回切换多份任务。==

    - 问题来了：主线程执行完毕后即使协程没有执行完毕，程序也会退出。

      解决：使用 `sync.WaitGroup` 等待协程执行完毕

      - 开启协程时，`wg.Add(1)`
      - 协程中的任务完成时，写在函数的最后 `wg.Done()`
      - 主程序中的最后：`wg.Wait()`

    - go1.5之后，默认的cpu是用电脑所有的kernel `runtime.NumCPU()`，设置cpu的数量：`runtime.GOMAXPROCS(cpu数量)`

    - **管道**：是Golang在语言级别上提供的 goroutine 间的通讯方式，我们可以使用channel 在多个 goroutine 之间传递消息。如果说goroutine是Go程序并发的执行体，channel就是它们之间的连接。channel 是可以让一个goroutine发送特定值到另一个goroutine的通信机制。

    - Golang 的并发模型是 CSP（Communicating Sequential Processes），提倡 **通过通信共享内存**，而不是 **通过共享内存而实现通信**。

    - 管道的阻塞：管道的容量不够放了、或者管道里没东西了再取。

    - 管道没有key，循环的时候直接：`for v := range ch{...}`，但是管道写入完成后必须关闭，否则 `for-range` 会死锁 `close(ch)`，但是直接 for 循环没事儿~

    - 素数统计

      ```go
      package main
      
      import (
      	"fmt"
      	"sync"
      )
      
      var wg sync.WaitGroup
      
      func putNum(intChan chan int) {
      	for i := 2; i < 120000; i++ {
      		intChan <- i
      	}
      	close(intChan)
      	wg.Done()
      }
      
      func primeNum(intChan chan int, primeChan chan int, exitChan chan bool) {
      	for num := range intChan {
      		var flag = true
      		for i := 2; i < num; i++ {
      			if num%i == 0 {
      				flag = false
      				break
      			}
      		}
      		if flag {
      			primeChan <- num
      		}
      	}
      	exitChan <- true
      	wg.Done()
      }
      
      func printPrime(primeChan chan int) {
      	for num := range primeChan {
      		fmt.Println(num)
      	}
      	wg.Done()
      }
      
      func main() {
      	// 从 intChan 取出数据，并判断是否为素数，如果是，就放到 primeChan
      	intChan := make(chan int, 1000)
      	primeChan := make(chan int, 1000)
      	// 标识primeChan退出
      	exitChan := make(chan bool, 16)
      
      	// 存放数字的协程
      	wg.Add(1)
      	go putNum(intChan)
      	// 统计素数的协程
      	for i := 0; i < 16; i++ {
      		wg.Add(1)
      		go primeNum(intChan, primeChan, exitChan)
      	}
      	// 打印素数的协程
      	wg.Add(1)
      	go printPrime(primeChan)
      	// 判断exitChan是否存满值
      	wg.Add(1)
      	go func() {
      		for i := 0; i < 16; i++ {
      			<-exitChan
      		}
      		// 关闭primeChan
      		close(primeChan)
      		wg.Done()
      	}()
      
      	wg.Wait()
      	fmt.Println("main goroutine done")
      }
      ```

    - 单向管道 ==场景：把管道当参数传递==

      - 只写：`var chan1 chan<- int`
      - 只读：`var chan2 <-chan int`

    - select 多路复用 ==场景：同时响应多个管道的操作==

      - <u>主要是为了解决，多个chan的数据获取，要写多个for，但是for又是顺序执行的，无法做到同时取数的并发执行</u>

      - 类似switch，每个case对应一个管道的通信

      - 哪个管道来，就走哪个case

      - 一般结合for循环使用

      - **不需要关闭channel**，因为select case都阻塞了就会走default，而default直接return了，就不会死锁了

      - default的意思是，当其他case的数据稍微迟来了一丢丢，就会数案件执行default，如果default不return就会陷入死循环，**慎用**

        ```go
        for {
        	select {
        		case v := <- chan1:
        			...
                case v := <- chan2:
                	...
                default:
                	fmt.Println("数据获取完毕")
                	return
        	}
        }
        ```

    - goroutine recover解决协程中出现的panic

      在协程的执行函数中，记得写

      ```go
      defer func(){
      	if err := recover(); err != null {
      		fmt.Println("发生错误：", err)
      	}
      }()
      ```

    - 互斥锁

      - 问题：如果同时读取一个 `count++` 的值，可能会导致竞争 `go build -race main.go`

      - 解决：对共享资源进行访问控制

        ```go
        var mutex sync.Mutex
        
        // 加锁
        mutex.Lock()
        // 操作资源
        ...
        // 解锁
        mutex.Unlock()
        // 完成
        wg.Done()
        ```
        

    - 读写互斥锁：可以让读操作并发，同时读取；对于写操作完全互斥

35. 反射

- `v := reflect.TypeOf(x)`：获取x的类型
  - `v.Name()`：类型名称（比如自定义的 Person），不是都有名称的
  - `v.Kind()：`类型种类（底层类型，比如 struct），`[3]int` 数组的类型是 **array**，`[]int` 切片的类型是 **slice**

- `v := reflect.ValueOf(x)`
  - `v.Kind()`：可以配合 `switch-case` 来使用了
  - `case reflect.Int`、`case reflect.Float32`、。。。
  - `v.setValue(。。。)`：传入值类型是没法修改的，也不能直接获取地址，正确的方式是通过，先获取指针【就是说x是个指针】，再设置值：`v.Elem().SetInt(123)`


36. 结构体反射

    - `t := reflect.TypeOf(x)`：获取x的类型

    - :one: `field := t.Field(index)`：获取第 index 个参数/字段，这是一个结构体，可以通过 `field.Name`、`field.Type`、`field.Tag` 等等获取

    - :two: `field, ok := t.FieldByName("Name")`：获取指定的 参数/字段

    - :three: `fieldCount := t.NumField()`：获取结构体有多少个 参数/字段

    - :four: 获取结构体属性对应的值，`v := reflect.ValueOf(x)`：可以直接用 v 去获取结构体对应的值，比如 `v.FieldByName("Name")`

    - **结构体方法** 获取的方式是相似的，比如 `t.Method(0)`，这里的0跟顺序没关系，跟结构体方法的 ASCII 码有关。所以用的比较多的还是 `t.MethodByName("方法名")`；类似的，如果要执行的话，就用从值里获取 `v.Method(0).Call(nil)`，有参数就写参数，没参数就写 nil

    - 参数的编写方式，记得传参的x要传指针，才能通过反射修改值

      ```go
      var params []reflect.Value
      params = append(params, reflect.ValueOf("李四"))
      params = append(params, reflect.ValueOf(18))
      
      v.MethodByName("SetInfo").call(params)
      ```

    - 可以在执行的时候加入对 **指针类型** 和 **结构体指针类型的判断** 【讲道理，我觉得判断后者就够了】 `if t.Kind() != reflect.Ptr || t.Elem().Kind() != reflect.Struct {}`

37. **不要乱用反射**

    1. 基于反射的代码是极其脆弱的，反射中的类型错误会在真正运行的时候才会引发 panic ，那很可能是在代码写完的很长时间之后
    2. 大量使用反射的代码通常难以理解

38. 文件

    1. 读取文件

       - `os.Open()`，只读打开
       - `bufio`
       - `ioutil`，这里已经废弃了，直接用 `io.ReadFile()`，这个跟之前的缓存流读取不同，是直接一次性读取所有内容，对小文件合适

       ```go
       package main
       
       import (
       	"fmt"
       	"io"
       	"os"
       )
       
       func main() {
       	file, err := os.Open("./main.go")
       	if err != nil {
       		fmt.Println(err)
       		return
       	}
       	defer file.Close()
       	// 操作文件
       	var strSlice []byte
       	var tempSlice = make([]byte, 128)
       
       	for {
       		n, err := file.Read(tempSlice)
       		if err == io.EOF { // 文件读取完毕
       			break
       		}
       		if err != nil {
       			fmt.Println(err)
       			return
       		}
       
       		fmt.Println("读取了：", n, "字节")
       		// 注意这里的 :n 写法
       		strSlice = append(strSlice, tempSlice[:n]...)
       	}
       	fmt.Println(string(strSlice))
       }
       ```

       ```go
       package main
       
       import (
       	"bufio"
       	"fmt"
       	"io"
       	"os"
       )
       
       func main() {
       	file, err := os.Open("./main.go")
       	if err != nil {
       		fmt.Println(err)
       		return
       	}
       	defer file.Close()
       
       	var fileString string
       	reader := bufio.NewReader(file)
       	for {
       		// 一次读取一行数据
       		str, err := reader.ReadString('\n')
       		if err == io.EOF {
       			fileString += str
       			break
       		}
       		if err != nil {
       			fmt.Println(err)
       			return
       		}
       		fileString += str
       	}
       	fmt.Println(fileString)
       }
       ```

39. 泛型

    - 我感觉是解决了空接口变量的**断言**的问题

    - 泛型的类型不一定是any，也可以通过 type 定义几种类型的 接口 来约束类型

      ```go
      package main
      
      import "fmt"
      
      type Number interface {
      	int | int32 | int64 | float64
      }
      
      func getDataInterface[T Number](value T) T {
      	return value
      }
      func main() {
      	// str1 := getDataInterface("hello")
      	// str2 := getDataInterface(123)
      	// str3 := getDataInterface(true)
      	// fmt.Println(str1, str2, str3)
      	fmt.Println(getDataInterface(123))
      }
      ```

    - 类似的，结构体也可以用泛型来完成复用，实例化的时候传入具体的类型，就可以完成约束

      ```go
      type Container[T any] struct {
      	value T
      }
      
      func (c *Container[T]) Set(value T){
      	c.value = value
      }
      
      func (c *Container[T]) Get() T{
      	return c.value
      }
      ```

2. gin的返回

   - `gin.H{数据}` 就等同于 `map[string]any{数据}`

   - **jsonp**：跨域处理的请求，现在应该很少用这种方案了；**JSONP（JSON with Padding）是早年用来跨域的老方案**。原理：利用 `<script>` 标签不受同源策略限制的特点，把 JSON 包在一个函数调用里返回。

     - 请求带上 `callback` 查询参数：`/api?callback=func1`
     - Gin 检测到 `callback`，返回：`func1({"foo":"bar"})`，`Content-Type: application/javascript`
     - 前端提前定义好 `func1`，浏览器拿到这段 JS 自动执行，拿到数据
     - 如果没有传 `callback`，行为退化成普通 `c.JSON()`，直接返回 JSON

     > 👉 一句话总结：**Gin 保留 JSONP 只是为了兼容历史，现代业务跨域全部用 CORS**。
     >
     > **❌️ JSONP 的硬伤（为什么被淘汰）**
     >
     > 1. **只能 GET**，POST/PUT/DELETE、上传文件都不行，URL 还有长度上限
     > 2. **安全风险高**：返回的是可执行 JS，一旦服务端被劫持，直接在页面执行恶意代码（XSS）；也容易被 CSRF 利用
     > 3. **错误处理拉胯**：404/500 拿不到状态码，只能靠超时猜失败
     > 4. **不能自定义请求头**（Authorization、自定义 header 都没法带）
     >
     > **✅️ CORS（现代标准方案）**
     >
     > 后端配置响应头 `Access-Control-Allow-Origin`，浏览器原生支持 fetch/axios，支持所有请求方法、状态码、自定义头、credentials，安全可控，是现在的标准做法。 Gin 直接用 CORS 中间件即可，非常成熟。

   - 可以返回xml、json、jsonp、html、string，直接用 `c.HTML(...)` 实现
